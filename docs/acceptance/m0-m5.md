# Testing M0–M5 by hand

A walk-through to check the M0–M5 build on your Mac. Every step names the design frame it should match (`design/Relay.fig`).

## 0. Build and open

```bash
cd apps/relay && flutter build macos --release
```

```bash
open build/macos/Build/Products/Release/Relay.app
```

- The app starts relayd from `Contents/Helpers/relay`. **Settings** shows its pid, memory and data folder.
- **Agents** lists the CLIs found on your login shell's PATH, plus the built-in **Demo agent**.
- To use Claude Code, sign its CLI in first: run `claude /login` in Terminal. On 2026-10-11 the login on this Mac had expired, so headless `claude -p` runs failed.

## 1. A multi-repo project (T11)

1. In the sidebar, choose **Projects +**. Name the project, then **Add folders…** and pick 2–6 git repos.
2. **Repos** view:
   - Each repo shows its detected stack, base branch and test command.
   - Edit a repo (**…** → Edit) to set **Depends on**, **Contracts** (e.g. `openapi.yaml`) and the **Merge step**.
   - The repo map draws the dependencies, and the merge order panel follows the merge steps.
3. The sidebar shows the project's repos under it. Clicking one filters the board.

## 2. A cross-repo task with a live agent (T05, T02, T12)

1. Press **⌘N**. Type a title that mentions UI and an API, e.g. *"Share button on the recipe screen calling a new share-link endpoint"*.
   - Relay suggests repos. Add them.
   - Leave **Who** on *Demo agent*, or pick Claude Code once it is signed in.
2. **Create and queue**. The card moves to **Running**, and the sidebar shows the agent's slot in use.
3. Open the task:
   - The run pane streams steps.
   - The permission card asks to **Write**: choose **Allow once**.
   - Type in **Steer the run…**; the message goes to the agent.
4. When it finishes, the task moves to **Review**. The change set lists one row per repo with its diff.
   - **Diff** shows the branch against its base.
   - **Merge in order** merges each repo's branch into its base branch, step by step.
5. Look in your repos: each has a `Merge KT-1: …` commit. The **Git** view shows the commits with the agent and task.

## 3. Workspace safety (M5-02)

- Look in `~/Library/Application Support/Relay/workspaces/<key>/<key>-N/`:
  - repos the task changes are worktrees on branch `<key>-N`;
  - the others are **read-only** snapshots;
  - `PROJECT.md` maps the repos.
- Your own checkouts are never written until you merge.

## 4. Pipelines and scheduling (T05, T08)

1. In ⌘N choose **Pipeline**: Plan (agent) → Build (agent) → Review (you). Each step runs in turn, and the task waits in Review for you.
2. **Timeline** shows runs per agent slot and a now line. Queued tasks appear as scheduled bars you can drag to another time.
3. **Agents → Routing rules**: add *If tag is tests then …*. A task tagged `#tests` with *Any agent* goes to that agent.
4. **Stop after** in ⌘N stops a stuck run. A **Daily cap** on an agent card keeps it from starting once today's spend reaches the cap.

## 5. Code, terminal, take over (T10, T09)

1. **Code** view:
   - Pick a repo, or a task's workspace (all its repos in one tree).
   - Open a file, edit it, **⌘S**.
   - **New task from selection** starts a task with the snippet.
2. The terminal is a real shell in that folder.
3. While an agent runs, its mirror shows next to your shell. **Take over** pauses the agent and opens a shell in its workspace; **Hand back** resumes it.
4. **Git** view: the commit graph per repo, or **All repos** tagged by repo, with commit details.

## 6. Agents talking to Relay and each other

Agents get `relay` MCP tools for every run (`relay_progress`, `relay_ask`, `relay_message_agent` …).
- When an agent asks a question, the task shows **Asks you**. Your reply in the discussion goes straight back to the agent.
- When a run changes a contract file, Relay posts a notice and tells the other agents working on that task.

## 7. Performance

With the app idle on the board, run:

```bash
tool/perf_check.sh 60
```

Both rows should say `ok` (ADR-0001 budget).
