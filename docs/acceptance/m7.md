# Testing M7 (Worker, live, channels, notifications) by hand

M7 builds on the M6 team setup. For one-Mac testing, run a second Relay on its own data folder as in [m6.md](m6.md).

## 1. Deploy the team Worker (M7-01)

1. Create an API token at dash.cloudflare.com → My Profile → API Tokens → Create Token → Custom. Grant:
   - *Account → Workers Scripts → Edit*
   - *Account → Workers R2 Storage → Edit*

   Scope it to your account.
2. Note the account ID from the Workers & Pages overview.
3. In Relay, open **Settings → Team → Create a team** and choose **Cloudflare Worker**.
4. Fill in the account ID and token, then choose **Test connection**. Expected: *The token can deploy Workers…*.
5. Choose **Create team**. The progress line shows four steps: bucket, upload, workers.dev, waiting.
   - Expected: the Team box shows `relay-<team>.<you>.workers.dev (Worker)` and *live · 1 online*.
   - In the Cloudflare dashboard, the Worker `relay-<team>` has a Durable Object `TeamRoom`, and R2 has a bucket `relay-<team>`.
6. Or from Terminal:

   ```bash
   CLOUDFLARE_API_TOKEN=… relay worker deploy --account <id> --team binarycastle
   ```

7. Invite a teammate (**Invite teammate…**). Decode the code's base64 part: it holds only the Worker URL, no keys.

## 2. Live (M7-02)

1. On both Macs, set **Sync every** to 5 min, so polling can't be what moves things.
2. Edit a task on Mac A. It shows on Mac B within about 4 seconds: a 3 s local debounce, then a poke.
3. Start an agent run on A. Open the same task on B: earlier steps load, and new steps appear on B within a second.
4. Quit relayd on B, or turn Wi-Fi off. A's Team box drops to *1 online*. Bring B back and it reconnects by itself.
5. Remove B on A (**Devices → remove**). B shows *removed from the team* at once, because its socket closes with code 4001. Its storage access is gone: the token no longer works.

## 3. Channels (M7-03, T04)

1. The sidebar lists **Channels**: `#general` and one per project, e.g. `#taskmanager`. Team members appear under **Team** with their shared agent.
2. In `#taskmanager`, type `/task @demo add golden tests for the channel view`. The button reads **Create task**. Expected:
   - a message with a task card showing *Queued*;
   - the task on the board, assigned to the Demo agent;
   - when the run ends, *Demo agent* (tagged `AGENT · THIS MAC`) posts its summary in the channel.
3. Type `The board drag feels laggy. @codex can you profile it?`, where Codex is a teammate's shared agent. A task is made with Codex on their Mac, and Codex answers *Made a task from that on Sara's Mac — starting as soon as a slot frees.*
4. Type `@`: suggestions list this Mac's agents, teammates' shared agents, and people. Tab or Enter picks the first.
5. Hover a message to react (👍 ✅ 👀, or the picker), pin, or delete your own. Reactions from two Macs at once both stay.
6. Attach a file with the paperclip. It shows *stored in your team storage · encrypted*. A teammate clicks it and it opens. In the bucket it is `files/<id>.bin`, starting with `RLY1`.
7. The next morning after 08:00 (setting `digestHour`), each project channel gets one **DIGEST** message listing the last 24 h of runs. It appears once even with several Macs.
8. Unread counts appear next to channels and clear when you open them.

## 4. Notifications (M7-04)

1. The first notification asks for permission. Allow it in the macOS prompt.
2. With Relay in the background:
   - an agent asking for permission or with a question → *TM-12 needs your OK*;
   - your task done → *TM-12 is ready for review*;
   - a teammate writing `@rifat` → *Sara in #taskmanager*.
3. Clicking a notification opens that task or channel.
4. With Relay in front, no banners appear. Mentions in other channels show a toast with **Open**.
5. The Dock badge shows how many tasks are *Waiting on you*.
